# Theme discovery

Ticket 08 extends the existing `/api/analyze` decision pipeline. Its only direct blocker is ticket 05. It does not depend on the new-cash screen, portfolio re-underwriting or the later Canadian evidence extension.

Choose **Explore a theme** in the existing question form. Name the theme and an economic mechanism that can be challenged with evidence, select one to four supplied US stocks or ETFs (zero-share candidates are allowed), set a maximum candidate count and a maximum tool-call effort, then explicitly confirm agreement. Changing the mechanism, shortlist, bound, snapshot or comparison facts clears confirmation. An unconfirmed submission returns a completed clarification without model calls or candidate research, even without OpenAI configuration.

`theme` binds `name`, `mechanism`, `shortlist`, `max_candidates`, `max_tool_calls`, `confirmed`, and optional `risk_context`. The effort counts all model-requested portfolio, evidence, calculation and comparison calls, including optional financial tools. Allow portfolio review and comparison plus three calls per company (research, mechanism test, cases), or one mechanism test per ETF. The last model answer is outside this tool count. Exceeding the bound, repeated research, off-shortlist research, skipping required stages or researching after comparison fails closed without publishing a recommendation. There is no discovery scan, background crawl or automatic retry outside the bound.

After portfolio review, `research_candidate` exposes backend-owned SEC/issuer excerpts together. `test_theme_mechanism` records support, challenge or unknown, with an explanation and available candidate evidence IDs. Stock cases reuse operating judgments and the existing sector-appropriate Python calculations. ETF cases use sponsor exposure, income, fund costs and FX through the shared comparison calculations. The frontend reuses comparison inputs for dated sponsor facts and known costs/tax effects. Only agreed candidates and diversified fund alternatives may be comparison destinations; cash and actual no action are included on a common dated capital and reporting-currency basis.

Primary excerpts come from the existing backend-only `RESEARCH_REFERENCE_FILE`; this is reviewed source material, not live filing retrieval. Missing/conflicting data remains unknown. Agency/macro evidence is not available through these theme tools and is excluded from company research; no macro forecast is substituted. Canadian stock research is explicitly unavailable until the later evidence extension. Dated sponsor facts identify their original user-supplied source/link; they are not independently verified.

A supported mechanism does not compel a purchase. No action can preserve the snapshot despite unknown transaction effects; missing decisive mechanism/company evidence produces conditional guidance. An evidence-supported preferred addition can call the existing `size_review` helper after comparison with a justified exposure range and same-account/currency cash. The shared Python helper checks risk context, verified dated source inputs, zero supported cost/tax effects, funding and both company-cap/active-budget endpoints. Existing same-listing fund exposure is aggregated across accounts before sizing an ETF addition. Unknown decisive inputs or nonzero funding effects leave amounts undetermined. A conditional, amountless purchase alternative does not replace a supported no-action conclusion. No allocation screen or personal context is invented. Existing caps, active budget, valuation and overlap checks remain authoritative. Model trade previews must exactly match explicit user-supplied changes. No orders, invented probabilities or execution claims are accepted.

`theme` in the validated result contains the agreed context, status, researched IDs, evidence-linked mechanism tests, calculated stock cases, calls used and qualifications. The existing comparison and recommendation display gives serious alternatives, costs, pivotal drivers, downside, uncertainty and what could change the view.

Verification uses API boundary tests with scripted models and reviewed fixtures, the production OpenAI adapter with a fake HTTP transport, and a complete browser agreement-to-result journey against local fake services. External network connections are blocked. See `ticket-08-review.md` for separate review of completed controlled answers; scripted answers verify behavior, not live AI reasoning quality.
